# 表ハルキュー：教科書フォーメーション H1

2026-10-30、ユーザーが教科書に沿ったコード追加と自動選択の新規実装を承認。
資料：`keirin_3rentan_formation_manual_latest.pdf`（40ページ、Library ID `libfile_30aa4d12f5e08191990a4239a0fd7780`）。

## 実装した対応

|教科書|実装|
|---|---|
|9–10頁 1着固定|上位候補1人を固定、相手3/4/5人の順序を残す|
|11、13–14頁 表裏・順序固定・3着流し|同ライン隣接役割、異線の代表候補から作る|
|12、15頁 ハサミ|一方を1着、他方を3着に置く|
|16–17頁 2着固定・3着固定|勝つ人だけを軸にしない候補生成|
|19頁 複数勝者|上位3人を1・2着候補、3着を4人に拡張|
|20、33頁 複数展開|表裏とハサミを別ブロックのまま合成、組番重複を除外|
|30–34頁 全体価格|全点投資を分母に期待払戻、合成オッズ、追加費用を計算|

候補内の単独期待値が100%未満の組番を除去しない。ブロックを追加したときの独自点数・費用・仮説上の確率増分も出力する。
並びは出走表の全車分が必要。欠車・未知車番・重複・不完全な並びは推測しない。
同じ形へ各欄の候補をまとめるだけで、意図しない組番を増やすことはしない。

## 教科書にない新規仮説 H1

教科書は購入例と組み方の説明であり、自動選択の数式・利益が証明された方法ではない。
今回のH1も未知期間で未検証。

- 候補人数、上位3人の軸候補、24点上限、各100円は実装上の新規仮説。
- 同ラインは先頭/番手だけでなく番手/3番手など隣接役割を候補にする。異線は各ラインのモデル最上位選手を代表候補とする。実際の主導権や消耗を判定できたとは扱わない。
- 既存スコアに温度1のPlackett–Luceを適用し全3連単を正規化する。**未較正の仮説値で、独立3連単V6の確率ではない。ライン連動を表現できない**。ラインは形の生成に使う。
- オッズがない場合は `形の仮説確率 − 0.01 × 点数` 最大を研究候補として自動選択。0.01も未検証の仮説である。
- オッズがある場合は候補すべての組番の価格を要求。集合全体の仮説期待回収率>1、合成オッズ>=3.0の候補から仮説期待利益最大を選ぶ。単独EVでの除外は行わない。
- 合成オッズ `1 / Σ(1/odds)` は均等購入の払戻倍率ではない。均等購入の期待回収率は `Σ(p×odds)/点数`。最低的中回収率も別に計算する。
- 元の3連単参加条件を継承する。F2は現在のルールどおり研究候補も出さない。

## 接続と実行

通常の `scripts/flagship_live_predict.py` 実行で `formation_strategy` と全車の `line_formation` を自動出力する。
個別・日別Webも形と点数を表示する。公開時は候補を再計算し、不一致なら停止する。
旧記録にないフィールドは追加しない。過去Web履歴は書き換えない。

**この段階の出力は研究候補である。`counts_as_purchase=false`、判定は見送り。既存の購入ロジック・購入額への切り替えは実装していない。**
元モデル・44特徴量・予測順位・元買い目は変更しない。

保存予測からの再実行：

```bash
python -m scripts.haruq_formation_replay --source forecast.json --out formation.json
python -m scripts.haruq_formation_replay --source forecast.json --market market.json --out formation.json
```

`market.json` は `{"race_id":"対象ID", "odds":{"1>2>3":20.5}}` の形式。候補全体に価格が必要。通常ライブ経路には3連単オッズ取得がないため、価格比較はこの入力経路を使う。確定払戻を購入前オッズに偽装しない。
